1. WHAT ARE MEDIA QUERIES?
---------------------------

Media queries are used when I want my website layout to
change according to the screen size.

The basic syntax is:

    @media (condition) {

        /* CSS */

    }

For example:

    @media (min-width: 768px) {

        .layout-container {
            flex-direction: row;
        }

    }

This means the styles inside the media query will apply
when the screen width is 768px or more.


MIN-WIDTH
---------

`min-width` means that the CSS will apply from that width
and above.

Example:

    @media (min-width: 768px)

So:

    768px and above
    = apply these styles


MAX-WIDTH
---------

`max-width` is the opposite.

It means the CSS will apply up to a certain width.

Example:

    @media (max-width: 767px)

So:

    767px and below
    = apply these styles


BREAKPOINTS
-----------

A breakpoint is basically a screen width where I decide
that my layout needs to change.

In today's practice I used:

    768px
    1024px

At 768px, I changed the layout and cards.

At 1024px, I gave the cards even more space by showing
four cards in one row.

I understood that these numbers are not compulsory.
They are just points where I decide that my current
layout needs to change.


2. WHAT IS MOBILE-FIRST APPROACH?
-----------------------------------

Mobile-first means I design the smaller screen layout
first and then add changes for larger screens.

The basic idea is:

    Mobile
       |
    Tablet
       |
    Desktop


DESKTOP-FIRST vs MOBILE-FIRST
------------------------------

Desktop-first means I start with the large-screen design
and then make changes for smaller screens.

Mobile-first means I start with the small-screen design
and then add styles for larger screens.

In my code, I used the mobile-first approach.

For example, my layout starts with:

    .layout-container {
        display: flex;
        flex-direction: column;
        gap: 15px;
    }

So on a small screen the boxes are placed one below
another.

Then I used:

    @media (min-width: 768px) {

        .layout-container {
            flex-direction: row;
        }

    }

Now when the screen becomes wider, the boxes can appear
in a row.

I did the same thing with the cards.

First I used:

    .cards-container {
        display: grid;
        grid-template-columns: 1fr;
    }

This means one card per row.

Then at 768px:

    grid-template-columns: repeat(2, 1fr);

Now I get two cards per row.

Then at 1024px:

    grid-template-columns: repeat(4, 1fr);

Now all four cards can fit in one row on a larger screen.

This made mobile-first easier for me to understand because
I could start with a simple layout and then add more
columns when there was enough space.


3. FIXED WIDTH KA MASLA
--------------------------

While practicing responsive design, I also understood
why fixed widths can cause problems.

For example:

    width: 1100px;

This forces the element to be 1100px wide.

But what if the screen is only:

    400px
    500px
    600px

The element can become wider than the screen.

This can cause horizontal scrolling and make the website
difficult to use on smaller screens.


MAX-WIDTH
---------

Instead of forcing a fixed width, I can use:

    max-width: 1100px;

For example:

    main {
        max-width: 1100px;
        margin: 20px auto;
        padding: 0 20px;
    }

This means the content can grow up to 1100px, but it can
also become smaller when the screen is smaller.


WIDTH vs MAX-WIDTH
-------------------

    width: 1100px;

means:

    Make the element 1100px wide.


    max-width: 1100px;

means:

    Don't allow the element to become wider than 1100px.

This difference became much clearer when I tested the
page at smaller screen sizes.

6. MISTAKES I IDENTIFIED
----------------------------

Mistake 1: Putting @media in the wrong place
----------------------------------------------

I initially thought of @media like a normal CSS property
and tried to place it inside a selector.

But media queries should be written as separate CSS blocks.

Correct structure:

    .cards-container {
        /* normal styles */
    }

    @media (min-width: 768px) {

        .cards-container {
            /* responsive styles */
        }

    }

This helped me understand how media queries are actually
structured.


Mistake 2: Duplicate selectors
---------------------------------

While working on the CSS, I had duplicate selectors like:

    .cards-container

and:

    .layout-container

in different places.

The CSS can still work, but it becomes harder to understand
which rule is changing the final result.

This reminded me about the CSS cascade from previous days.

I should try to keep related styles together and avoid
unnecessary duplicate selectors.


Mistake 3: Empty @media blocks
---------------------------------

During testing, I also left some empty media query blocks.

For example:

    @media (min-width: 768px) {

    }

There is no reason to keep an empty block because it
doesn't do anything.

So I learned that cleaning the CSS after testing is also
important.


Mistake 4: Not testing different screen sizes
--------------------------------------------------

At first, a responsive page can look fine on one screen
size.

But that doesn't mean it will work everywhere.

I learned that I should resize the browser and test
different widths.

This helped me notice how the layout changes between
mobile and larger screens.
