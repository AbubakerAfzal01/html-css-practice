1. WHAT IS A LANDING PAGE / CSS MINI PROJECT
--------------------------------------------

A landing page is a webpage designed to present a product,
service, business, or idea in a clear way.

It usually contains different sections so the user can
understand the purpose of the website and interact with it.

In this project, I created a coffee shop landing page called:

    The Coffee Nook

The main sections I created were:

    - Navbar
    - Hero Section
    - About / Our Story
    - Features / Why Us
    - Menu
    - Contact
    - Footer

The main purpose of this project was to combine the CSS
concepts I learned from previous days and use them together
in one complete webpage.


CONCEPTS USED FROM PREVIOUS DAYS
--------------------------------

I used several concepts that I had already practiced:

    - Flexbox
    - CSS Grid
    - CSS Variables
    - Box Model
    - Pseudo-classes
    - Transitions
    - Transform
    - Responsive Design
    - Media Queries
    - clamp()
    - max-width
    - object-fit

For example, I used Flexbox in the navbar:

    .navbar {
        display: flex;
    }

I used Grid for the feature cards:

    .features-grid {
        display: grid;
        grid-template-columns: repeat(3, 1fr);
    }

I used a pseudo-class for hover:

    .feature-card:hover {
        transform: translateY(-5px);
    }

I used a media query for responsive design:

    @media (min-width: 768px) {
        ...
    }

I used clamp() for the hero heading:

    font-size: clamp(1.8rem, 4.5vw, 3.5rem);

This project helped me understand that CSS concepts are
not always used separately.

I can combine different concepts to create one complete
webpage.

2. CSS VARIABLES AND BASE STYLES
--------------------------------

CSS Variables allow me to store values once and reuse
them in different places in my CSS.

In this project, I created variables inside :root.

    :root {
        --main-color: #5c3a21;
        --main-font: 'Arial', sans-serif;
        --bg-light: #faf7f2;
        --text-dark: #2b2520;
        --hero-bg: #f3edd7;
        --dark-brown: #3d1d06;
    }

WHAT EACH VARIABLE DOES
-----------------------

--main-color
    This is the main brown color of the website.

--main-font
    This stores the main font.

--bg-light
    This is the light background color used in different
    parts of the website.

--text-dark
    This is the main dark text color.

--hero-bg
    This stores the background color of the hero section.

--dark-brown
    This is a darker brown color used for hover effects.

I can use these variables with:

    var(--main-color)
    var(--bg-light)
    var(--text-dark)

This makes the CSS easier to manage.

I also learned that if the same value is used in several
places, storing it as a variable makes future changes easier.


UNIVERSAL SELECTOR
------------------

I used:

    * {
        margin: 0;
        padding: 0;
        box-sizing: border-box;
    }

The * selector targets all elements.

margin: 0
    This removes the browser's default margin.

padding: 0
    This removes the browser's default padding.

box-sizing: border-box
    This makes the declared width and height include
    the element's padding and border.

Removing the default spacing means I need to add my own
spacing where necessary.

For example:

    margin-bottom: 40px;

was used for section headings.


HARDCODED COLOURS
-----------------

Earlier in the project, I changed several hardcoded
colours into CSS variables.

Later, when the CSS was rewritten, some hardcoded colours
appeared again.

Examples include:

    #000000
    #f6f5f4
    #e2ddda
    #a88a73
    #8b5a2b
    #ccc
    #ffffff

This showed me that rewriting a file can remove changes
that I had already made.

So before pushing the project, I need to check the final
CSS and make sure earlier improvements are still there.

3. NAVBAR AND HERO - FLEXBOX
----------------------------

NAVBAR
------

I used Flexbox on the navbar:

    .navbar {
        display: flex;
    }

I used Flexbox because I wanted to arrange the logo and
navigation links in a flexible layout.

On smaller screens, I used:

    flex-direction: column;

This makes the navbar content appear vertically.

At 768px and above, I changed it to:

    flex-direction: row;

This changes the navbar into a horizontal layout.

I also used:

    justify-content: space-between;

This places the logo and navigation on opposite sides
of the available space.


NAVIGATION LINKS
----------------

I used another Flexbox container:

    .nav-links {
        display: flex;
        flex-wrap: wrap;
        justify-content: center;
        gap: 8px;
    }

flex-wrap allows the links to move onto another line if
there is not enough horizontal space.

gap creates space between the navigation links.


HERO SECTION
------------

For the hero section I used:

    .hero-section {
        display: flex;
        justify-content: center;
        align-items: center;
    }

justify-content: center
    centers the content horizontally.

align-items: center
    centers the content vertically.

This allowed me to place the hero content in the center
of the section.

I also used:

    min-height: 70vh;

vh means viewport height.

70vh means the minimum height is approximately 70% of
the browser viewport height.

I used min-height instead of a fixed height because the
section can grow if the content needs more space.


CTA BUTTON
----------

My CTA is an anchor element:

    <a href="#menu" class="cta-button">Check Menu</a>

I used:

    display: inline-block;

An anchor is normally an inline element.

Using inline-block allows the anchor to behave more like
a box so I can control its size, padding and transform.

An important detail is that transform does not apply to
normal inline elements.

Padding on an inline element can appear visually, but it
does not behave like the spacing of a normal block-level
box around surrounding content.

Using inline-block makes the CTA easier to size and
transform.

I also used:

    padding: 12px 28px;

to make the CTA larger and easier to click.


CLAMP()
-------

For the hero heading I used:

    font-size: clamp(1.8rem, 4.5vw, 3.5rem);

clamp() takes three values:

    Minimum
    Preferred
    Maximum

In my example:

    Minimum    -> 1.8rem
    Preferred  -> 4.5vw
    Maximum    -> 3.5rem

This allows the heading size to change according to the
viewport while staying between the minimum and maximum
values.


HERO DESIGN DECISION
--------------------

I kept the word "You" in the hero design as a deliberate
design choice to make the main message feel more direct
and personal.

4. GRID CARDS - FEATURES AND MENU
---------------------------------

FEATURES GRID
-------------

I used CSS Grid for the feature cards.

The default mobile layout is:

    .features-grid {
        display: grid;
        grid-template-columns: 1fr;
        gap: 25px;
    }

This creates one column on smaller screens.

At 768px and above, I changed it to:

    grid-template-columns: repeat(3, 1fr);

repeat(3, 1fr) means:

    Create 3 equal columns.

It is similar to writing:

    grid-template-columns: 1fr 1fr 1fr;

The fr unit divides the available grid space into
fractions.


FR VS PX
--------

fr is mainly used to divide available grid space.

px represents a fixed pixel size.

Example:

    grid-template-columns: 1fr 1fr 1fr;

divides available space.

While:

    width: 200px;

represents a fixed 200 pixel width.


MAX-WIDTH
---------

I used:

    max-width: 1100px;

This prevents the content from becoming too wide on
large screens.

I also used:

    margin: 0 auto;

margin: 0 auto means:

    top/bottom -> 0
    left/right -> auto

When there is extra horizontal space, the automatic
left and right margins center the block.

I used this combination in:

    - features-grid
    - menu-list
    - contact-grid


OBJECT-FIT
----------

For the feature images I used:

    .feature-img {
        width: 100%;
        height: 200px;
        object-fit: cover;
    }

The images may have different original dimensions.

object-fit: cover allows the image to fill the given
area while keeping its aspect ratio.

Some parts of the image can be cropped, but the image
does not become stretched unnaturally.


MENU GRID
---------

On smaller screens I used:

    grid-template-columns: 1fr;

At 768px and above I used:

    grid-template-columns: repeat(2, 1fr);

So the menu changes from one column to two columns on
larger screens.

5. HOVER, FOCUS, TRANSITIONS, TRANSFORM AND ANIMATION
------------------------------------------------------

HOVER
-----

:hover is used when the mouse pointer is over an element.

For example:

    .feature-card:hover {
        transform: translateY(-5px);
    }

When I move the mouse over a feature card, the card moves
slightly upward.

I also used hover effects on:

    - Navigation links
    - CTA button
    - Feature cards
    - Menu items
    - Submit button


FOCUS
-----

:focus is related to an element receiving focus, such as
when using keyboard navigation.

I used:

    .nav-links a:hover,
    .nav-links a:focus

and:

    .cta-button:hover,
    .cta-button:focus

This gives the navigation links and CTA button a similar
visual state when they are hovered or focused.


TRANSFORM
---------

I used:

    transform: translateY(-5px);

This moves the feature card upward by 5 pixels.

For the CTA button I used:

    transform: scale(1.05);

This makes the button slightly larger when hovered.


TRANSITION
----------

I used transition in the normal/base rule.

Example:

    .feature-card {
        transition: transform 0.3s ease,
                    border-color 0.3s ease;
    }

Then the hover rule changes the properties:

    .feature-card:hover {
        transform: translateY(-5px);
        border-color: #a88a73;
    }

Putting transition in the base rule means the browser
smoothly animates both when the element enters the hover
state and when it returns to the normal state.


SLIDEUP ANIMATION
-----------------

In an earlier version of my CSS, I added a CSS animation
for the hero content.

I used:

    @keyframes slideUp

and:

    animation: slideUp 0.8s ease-out;

on .hero-content.

So the slideUp animation was actually implemented during
the project.

Later, when the CSS was rewritten, the slideUp code
disappeared from the file.

Therefore, the animation was part of an earlier version,
but it is not present in the latest CSS.

This taught me that after rewriting a file, I need to
compare the final version with my previous work so that
completed changes are not accidentally lost.

6. RESPONSIVE / MOBILE-FIRST
----------------------------

MOBILE-FIRST
------------

Mobile-first means creating the basic layout for smaller
screens first and then changing the layout for larger
screens.

In this project, the default CSS mainly provides the
smaller-screen layout.

For example:

    .features-grid {
        grid-template-columns: 1fr;
    }

This creates one column.

Then I use:

    @media (min-width: 768px)

to change the layout for larger screens.


WHY THE MEDIA QUERY IS AT THE END
---------------------------------

I placed the main media query near the end of the CSS.

The default/mobile rules are written first.

Then the larger-screen rules are written later:

    @media (min-width: 768px) {
        ...
    }

This makes the responsive changes easier to read and
allows the media-query rules to override the earlier
rules when the screen reaches 768px or wider.


NAVBAR AT 768PX
---------------

Before the media query:

    flex-direction: column;

At 768px and above:

    flex-direction: row;
    justify-content: space-between;

So the navbar changes from vertical to horizontal.


FEATURES AT 768PX
-----------------

Before:

    grid-template-columns: 1fr;

At 768px:

    grid-template-columns: repeat(3, 1fr);

This changes the feature cards from one column into
three columns.


MENU AT 768PX
-------------

Before:

    grid-template-columns: 1fr;

At 768px:

    grid-template-columns: repeat(2, 1fr);

This changes the menu into two columns.


CONTACT AT 768PX
----------------

Before:

    grid-template-columns: 1fr;

At 768px:

    grid-template-columns: 1fr 1fr;

This places the contact information and contact form
beside each other.


FORM BUTTON
-----------

On smaller screens:

    width: 100%;

So the button takes the full available width.

At 768px and above:

    width: auto;

So the button becomes only as wide as its content needs.
