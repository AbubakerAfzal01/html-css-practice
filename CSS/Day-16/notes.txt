1. WHAT ARE CSS CUSTOM PROPERTIES (VARIABLES)
----------------------------------------------

    CSS Custom Properties are basically CSS variables.

    In simple words, variables allow me to store a value once
    and reuse that value in different places in my CSS.

    For example:

        --primary-color: #34db74;


    I can then use this variable anywhere with:

        var(--primary-color)


    So instead of writing the same color again and again,
    I can store it once and reuse it.


    BASIC SYNTAX
    ------------

    A custom property starts with two dashes:

        --variable-name


    Example:

        --primary-color: #34db74;
        --spacing-md: 20px;
        --font-main: Arial, sans-serif;


    Then I use it with var():

        color: var(--primary-color);

        padding: var(--spacing-md);

        font-family: var(--font-main);


    :root
    -----

    I defined my variables inside :root:

        :root {
            --primary-color: #34db74;
            --secondary-color: #bf2ecc;
            --dark-color: #503e2c;
            --light-color: #ecf0f1;
        }


    :root represents the root element of the document.

    Defining variables there makes them available throughout
    the page.


    I also created variables for spacing:

        --spacing-sm: 10px;
        --spacing-md: 20px;
        --spacing-lg: 30px;


    And font variables:

        --font-main: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;

        --font-heading: 'Helvetica Neue', Arial, sans-serif;


    This made the CSS more organized because common values
    were stored in one place.


    CHANGE ONCE, UPDATE EVERYWHERE
    ------------------------------

    This was the main experiment I understood with variables.

    I used:

        --primary-color: #34db74;


    Then I reused it in different places.

    For example:

        .btn {
            background-color: var(--primary-color);
        }


    And:

        .nav-item:hover {
            color: var(--primary-color);
        }


    If I change the variable:

        --primary-color: red;


    all places using:

        var(--primary-color)

    automatically use the new value.


    So instead of changing the same color manually in
    multiple selectors, I only change it once.


    This is why I remember CSS variables as:

        "Change once, update everywhere."


    HOVER EXPERIMENT
    ----------------

    One interesting thing I noticed was with:

        .nav-item:hover {
            color: var(--primary-color);
        }


    I changed the value of:

        --primary-color


    and the hover color was also updated.

    But I could not see the change until I actually moved
    the mouse over the navigation link.

    This helped me understand that the variable value was
    already updated.

    The :hover rule simply becomes active when the hover
    state is triggered.

    So the variable was not waiting for hover to update.

    The value had already changed.

2. WHAT IS calc()
-----------------

    calc() is a CSS function that allows me to perform
    calculations when setting CSS values.

    It is useful when I need a value based on other values.

    Basic example:

        width: calc(100% - 40px);


    This means the width should be:

        100% - 40px


    In my project I used:

        width: calc(100% - var(--spacing-lg) * 2);


    Since:

        --spacing-lg = 30px


    the calculation becomes:

        100% - 30px * 2


    which means:

        100% - 60px


    So the box leaves space for both sides.


    OPERATORS
    ---------

    calc() can perform basic mathematical operations:

        +    Addition
        -    Subtraction
        *    Multiplication
        /    Division


    Example:

        width: calc(100% - 20px);


    Another example:

        width: calc(50% + 20px);


    And variables can also be used inside calc():

        width: calc(100% - var(--spacing-lg) * 2);


    This makes calc() more useful because I can combine
    variables with calculations.


    SPACES AROUND + AND -
    ---------------------

    One important thing I learned is that spaces are required
    around the + and - operators in calc().

    Correct:

        width: calc(100% - 20px);


    Correct:

        width: calc(50% + 10px);


    Writing:

        calc(100%-20px)

    can cause problems because CSS needs to recognize the
    + or - as an operator.


    So I remember:

        + and - -> use spaces around them


    Multiplication and division do not require the same
    spacing rule.

3. WHAT ARE min(), max(), clamp()
---------------------------------

    CSS also provides functions that help control values
    without writing a lot of media queries.

    The three functions I practiced today were:

        min()
        max()
        clamp()


    A. min()
    --------

    min() chooses the smaller value.

    Example:

        width: min(100%, 400px);


    This means the width will use whichever value is smaller:

        100%
        OR
        400px


    In my project I used:

        .responsive-box {
            width: min(100%, 400px);
        }


    So on a small screen, the box can become smaller because
    100% may be less than 400px.

    On a larger screen, the box will not grow beyond 400px.


    In simple words:

        min() = "Don't go above the smaller limit."


    This was useful for making the box responsive without
    manually writing different widths for different screens.


    B. max()
    --------

    max() does the opposite.

    It chooses the larger value.

    Example:

        width: max(300px, 50%);


    The browser uses whichever value is larger.


    So:

        min() -> smaller value

        max() -> larger value


    C. clamp()
    ----------

    clamp() is used when I want a value to stay between
    a minimum and maximum value while being flexible in
    between.

    The basic syntax is:

        clamp(minimum, preferred, maximum)


    I used:

        font-size: clamp(1rem, 3vw, 2rem);


    This means:

        Minimum  -> 1rem
        Preferred -> 3vw
        Maximum  -> 2rem


    So the font can scale according to the viewport width,
    but it will not become smaller than 1rem or larger
    than 2rem.


    I tested this with:

        .clamp-text


    When the browser size changes, the font size can change
    as well.

    But it stays inside the limits defined by clamp().


    SIMPLE DIFFERENCE
    -----------------

        min()
        -> chooses the smaller value


        max()
        -> chooses the larger value


        clamp()
        -> keeps a value between a minimum and maximum
           while allowing it to be flexible


    Easy way to remember:

        min   -> smaller
        max   -> larger
        clamp -> minimum + preferred + maximum

5. WHAT DID I UNDERSTAND?
-------------------------

    A. REAL-WORLD BENEFIT OF VARIABLES
    -----------------------------------

    Before learning variables, if I used the same color
    in many places, I would have to change every selector
    separately.

    For example:

        button
        navigation
        cards
        headings


    If all of them use the same main color, a variable
    makes this much easier.


    Instead of:

        color: #34db74;

    everywhere, I can use:

        color: var(--primary-color);


    Then if I want a different theme or color, I can change:

        --primary-color


    once.


    This is one of the main practical benefits of CSS
    variables.


    B. LESS REPETITION
    ------------------

    Variables also reduce repeated values in CSS.

    For example, instead of writing:

        20px
        20px
        20px
        20px


    I can define:

        --spacing-md: 20px;


    and use:

        var(--spacing-md)


    wherever I need it.


    C. RESPONSIVE DESIGN
    --------------------

    I also understood that functions like:

        min()
        max()
        clamp()


    can make responsive CSS easier.


    For example:

        width: min(100%, 400px);


    automatically adapts to available space.


    And:

        font-size: clamp(1rem, 3vw, 2rem);


    allows the font size to respond to the viewport while
    still having limits.


    This can reduce the need for writing many media queries
    for simple responsive situations.


    I understood that this does not mean media queries are
    completely unnecessary.

    Media queries are still useful when I need to change
    different layout rules at specific screen sizes.

    But functions like min(), max(), and clamp() can handle
    many simple responsive values directly.

6. MISTAKES I IDENTIFIED
------------------------

    1. AI-GENERATED HTML INCIDENT
    -----------------------------

    One thing I noticed during today's work was related to
    the HTML code.

    Some of the HTML was generated with AI instead of being
    written completely by me.

    The problem was not simply that AI wrote the code.

    The bigger problem was that I could not properly explain
    every part of the code when I looked at it.

    This reminded me that I am trying to actually learn
    HTML and CSS, not just produce a working page.

    So I need to understand the code I use instead of
    blindly copying it.

    My main lesson from this was:

        Don't just make it work.
        Understand why it works.


    2. ":root IS NOT APPLYING" CONFUSION
    -----------------------------------

    At one point I thought:

        :root is not applying.


    But the actual problem was not with :root itself.

    The problem was related to the way the CSS was being
    tested / displayed.

    Once I checked the complete page and proper browser
    environment, the variables were working.


    This taught me not to immediately assume that a CSS
    feature is broken.

    First I should check:

        - Is the CSS file connected?
        - Is the syntax correct?
        - Is the selector correct?
        - Is the variable defined?
        - Am I testing the complete page?


    3. TESTING ENVIRONMENT ISSUE
    ----------------------------

    Another thing I noticed was that a small preview does
    not always give the same experience as testing the
    complete HTML page in a normal browser.

    When working with responsive CSS, especially:

        min()
        clamp()
        vw
        percentages


    the browser viewport size matters.

    So I learned that if I want to properly test responsive
    behavior, I should test the complete page and resize
    the actual browser window instead of depending only on
    a small preview.
